# CheriusBot

A small, fully autonomous forecasting bot for the Metaculus **FutureEval** tournament
(Fall 2026) and **MiniBench**. It is built on the
[`forecasting-tools`](https://pypi.org/project/forecasting-tools/) package and follows the
structure of the official [Metaculus bot template](https://github.com/Metaculus/metac-bot-template).

> **AI disclosure.** All the code in this repository was written by Claude, an AI model made
> by Anthropic, under the supervision of the account holder. The forecasts and the comments
> posted on Metaculus are generated by an AI model as well, and every comment says so.

## What it does

For each open question it has not forecast yet:

1. **Research, once.** A web-search-enabled model writes a dated, sourced briefing: current
   state, recent news, base rates, scheduled events, unknowns. The prompt gives today's date
   and states that the question is not resolved yet.
2. **Forecast, several times.** The forecast model produces `PREDICTIONS_PER_QUESTION`
   independent forecasts (2 in the `cheap` profile, 3 in `full`). There is one prompt per
   question type (binary, numeric and discrete with percentiles, date, multiple choice). Each asks for a base rate, the arguments
   for and against, the status quo scenario, then the answer in a fixed format.
3. **Aggregate.** `forecasting-tools` combines the draws: median for binary and numeric
   questions, mean per option for multiple choice.
4. **Guard rails.** Binary probabilities are kept in [0.02, 0.98]; multiple-choice options are
   never 0 or 1 and sum to 1; numeric percentiles must strictly increase, otherwise the draw is
   discarded.
5. **Publish** the forecast and a comment with the research and the reasoning (private
   comment, the package default, as in the official template).

Design choices: no ensemble of models, no agent loop, no fine-tuning on tournament questions.
The Metaculus community prediction is never read or used.

## Tournament rules this bot is built to respect

- **No human in the loop.** Nobody reviews, edits or re-runs a forecast. A question that has
  been forecast is never forecast again (`skip_previously_forecasted_questions`). Do not
  re-run the bot by hand on a tournament question whose forecast you dislike, and do not tune
  prompts against open or upcoming tournament questions. Use `--mode test` for trials.
- **One prize-eligible bot per participant.** This repository drives a single Metaculus bot
  account. Do not run a second copy on another account for the prize.
- **A comment under every forecast**, posted together with it.
- **No copying of the community prediction.**
- The Metaculus bot account itself must be created by a human, who also handles identity
  checks and any contact with Metaculus. The bot never sends messages to anyone.

## Setup for the account holder

1. On Metaculus, create the bot account and copy its API token
   (<https://www.metaculus.com/futureeval/participate/>).
2. On OpenRouter, create an API key used by this bot only. **Set a credit limit on that key**
   and do not enable automatic top-up: this is the only hard cap (see "Cost").
3. Put this folder in its own GitHub repository (the `.github/` folder must sit at the
   repository root). A public repository gets free Actions minutes.
4. **Settings > Secrets and variables > Actions > Secrets > New repository secret.** Create
   exactly two secrets: `METACULUS_TOKEN` and `OPENROUTER_API_KEY`.
5. **Actions tab > enable workflows.** Scheduled runs do nothing yet: they wait for step 8.
6. **Actions > Forecast > Run workflow**, mode `test`, dry run checked (the default). This
   forecasts on at most 4 questions of `bot-testing-area` and publishes nothing. Read the log.
7. Run it again with dry run unchecked, and check on Metaculus (logged in as the bot) that the
   forecasts and the private comments appear.
8. Same page, **Variables** tab: create `BOT_ENABLED` with the value `true`. From then on the
   schedule (every 20 minutes) runs the tournament mode. Delete the variable to pause the bot.

Optional variables (same Variables tab): `BOT_PROFILE`, `BOT_MODEL`, `BOT_RESEARCH_MODEL`,
`BOT_PARSER_MODEL`, `BOT_MAX_USD_PER_RUN`, `BOT_MAX_USD_TOTAL`, `BOT_USD_PER_MTOK_INPUT`,
`BOT_USD_PER_MTOK_OUTPUT`, `PREDICTIONS_PER_QUESTION`, `MAX_QUESTIONS_PER_RUN`,
`LLM_MAX_TOKENS`, `OPENAI_API_BASE`.

GitHub pauses scheduled workflows after 60 days without repository activity, and scheduled
runs can start late when GitHub is busy.

### Running locally

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # fill in the two values; never commit this file
python main.py --mode test --dry-run
python -m pytest -q           # offline tests, no key needed
```

| Command | Effect |
| --- | --- |
| `python main.py --mode tournament` | Forecast on `fall-futureeval-2026`, `minibench` and `market-pulse-26q4` (`TOURNAMENT_IDS`) and publish |
| `python main.py --mode test` | Forecast on at most 4 questions of `bot-testing-area` and publish (re-forecasting allowed there) |
| `... --dry-run` | Same, but nothing is sent to Metaculus |

The process exits with code 1 if a question failed or a tournament could not be listed, so a
failed run shows red in Actions. Questions put off for lack of budget or time are not failures.

## Models and provider

| Variable | Default | Role |
| --- | --- | --- |
| `BOT_PROFILE` | `cheap` | `cheap`: `openrouter/anthropic/claude-haiku-4.5`, 2 draws. `full`: `openrouter/anthropic/claude-opus-5.5`, 3 draws |
| `BOT_MODEL` | from the profile | Forecasts |
| `BOT_RESEARCH_MODEL` | `BOT_MODEL` + `:online` (OpenRouter only) | Research with web search |
| `BOT_PARSER_MODEL` | `openrouter/anthropic/claude-haiku-4.5` | Only used when an answer does not follow the format |

Model names use the litellm format. The key that must be set depends on the prefix:
`openrouter/...` needs `OPENROUTER_API_KEY`; `openai/...` needs `OPENAI_API_KEY` and, for any
OpenAI-compatible service, `OPENAI_API_BASE`; `anthropic/...` needs `ANTHROPIC_API_KEY`;
`metaculus/...` (Metaculus proxy credits) needs nothing more. Outside OpenRouter there is no
`:online` search: set `BOT_RESEARCH_MODEL` to a model that searches the web. The default names
could not be checked against the live OpenRouter catalogue before the first run.

## Cost

Estimates, not measurements. One question costs one research call and
`PREDICTIONS_PER_QUESTION` forecast calls, plus about $0.02 of OpenRouter web search:
roughly $0.05 to $0.08 in the `cheap` profile, $0.30 to $0.50 in the `full` profile. A season
has 300 to 400 tournament questions plus about 60 MiniBench questions every two weeks.

Spending caps, from the strongest to the weakest:

1. **Credit limit on the OpenRouter key**, prepaid, no automatic top-up. The only hard cap.
2. `BOT_MAX_USD_TOTAL` (default 55): once the estimated season spending reaches it, the bot
   forecasts nothing more and says so in the log. The total is the larger of the local ledger
   (`.budget/ledger.json`, carried between runs by the Actions cache) and the usage OpenRouter
   reports for the key. Set it to 0 to remove the cap, for instance when credits are granted.
3. `BOT_MAX_USD_PER_RUN` (default 1): a run stops calling the model once this is spent; the
   remaining questions wait for the next run. At most 3 questions are in flight, so the
   overshoot is a few calls.
4. A question that failed 3 times is given up (`BOT_MAX_ATTEMPTS_PER_QUESTION`), so a broken
   question cannot be paid for every 20 minutes.
5. `MAX_QUESTIONS_PER_RUN` (default 15, 4 in test mode) and `LLM_MAX_TOKENS` (default 4096).

When neither litellm nor the provider reports a cost, it is estimated from the token counts
and `BOT_USD_PER_MTOK_INPUT` / `BOT_USD_PER_MTOK_OUTPUT` (defaults: 1 / 5 in `cheap`, 5 / 25
in `full` or whenever `BOT_MODEL` is overridden). Set them to the real prices of your model.

## Known limits

- Conditional questions are not handled; they are skipped and logged.
- The package posts the forecast first and the comment second. If the comment call fails, the
  forecast stays without a comment and the question is skipped afterwards.
- If the research call fails or returns nothing, the question is not forecast in that run and
  is retried by a later run while it is still open (3 attempts at most).
- The ledger is an estimate. If the Actions cache is lost, it restarts from the usage reported
  by OpenRouter, or from zero with another provider.
